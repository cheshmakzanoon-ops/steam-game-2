# Phase 002 — Originality Brief

**Project:** Charterwake: The Last Relay  
**Status:** APPROVED ORIGINALITY BASELINE  
**Date:** 2026-09-22  
**Title status:** WORKING TITLE ONLY — trademark clearance incomplete

This brief defines the structural and visual distance Charterwake must maintain from every reference game. It is a production constraint, not a marketing comparison sheet.

---

## 1. Originality thesis

Charterwake is not "another compact kingdom game with a different activation gimmick."

Its strategic object is a **player-built physical command graph**:

- buildings expose cardinal signal ports;
- rotation changes topology;
- compatible ports form visible links;
- the Keep originates limited Command;
- structures consume Load;
- the player sets explicit priorities;
- switchgates can split one physical graph into operational circuits;
- relays alter reach/capacity;
- redundant paths can create Resonance;
- damage can sever links and create visible cut points;
- all outcomes recalculate under deterministic rules.

The game's primary recurring question is:

> **Which parts of this physical network deserve scarce authority now, given threats I can already see?**

No reference game in the comparison set may become the template for board layout, activation shape, icon family, progression, names, resource set, UI arrangement, encounter cadence, or marketing composition.

## 3. Command-network distinction

### 3.1 What Command is

Command is **operational authority**, not electricity, visibility, mana, worker assignment, attention radius, or a movable selection field.

A structure is eligible only if it has a valid path to the Keep through enabled links. Eligible structures then compete for finite Command according to explicit player priorities and deterministic tie-breaking.

### 3.2 What makes the graph visibly ours

The network must communicate, at gameplay scale:

- port orientation;
- physical adjacency;
- connection state;
- circuit separation;
- priority;
- Load;
- overload;
- isolation;
- vulnerable articulation/cut points;
- redundant paths / Resonance;
- predicted state after known damage.

The graph itself should be screenshot-legible. A screenshot that hides the network and could be mistaken for a generic kingdom roguelite fails the originality gate.

### 3.3 Undo contract

During planning, reversible topology edits must be previewable before the player commits to irreversible phase resolution. Undo must restore the authoritative prior state, including costs, orientation, links, priorities and derived network status.

No production/siege result may be silently rewound through presentation-only state. The exact final undo cadence is a later rules/UI decision, but the implementation may not depend on non-reproducible animation state.

### 3.4 Reload contract

A saved planning state must reconstruct the same graph from authoritative serialized data. Recalculation after reload must produce the same connectivity, priorities, Command allocation and derived labels for the same content version.

### 3.5 Failure contract

Network failure is expressed through explicit states, never hidden heuristics:

- isolated;
- disabled by switch;
- eligible but unpowered because Load exceeds capacity;
- damaged/severed;
- predicted to disconnect;
- powered;
- resonant.

If a player loses because a network link or priority choice mattered, the causal chain must be inspectable after the fact.

## 4. Names, icons, layouts and progression — banned imitation zones

### Names

Do not borrow recognizable naming patterns, faction names, building names, enemy names, upgrade names, achievement phrasing, currencies, or lore vocabulary from reference games.

Internal placeholder names copied from a reference are also prohibited because placeholders tend to survive.

### Layouts

Do not reproduce:

- another game's board dimensions because "it worked there";
- its screen partitioning;
- its resource strip placement;
- its card/choice panel geometry;
- its upgrade screen;
- its icon ordering;
- its HUD silhouette;
- its store screenshot composition.

Layout decisions must be derived from Charterwake's state hierarchy and accessibility requirements.

### Icons

Every icon family must originate from Charterwake's own semantic vocabulary: charter marks, ports, relay knots, seals, ledgers, watch signs, threat marks and material symbols.

Tracing, redrawing, recoloring or "simplifying" a competitor icon is still copying and is prohibited.

### Progression

Meta-progression primarily opens sideways possibilities: doctrines, structures, mutators, inks, lore, challenge options and sidegrades. It must not duplicate another game's unlock tree or rely on permanent universal stat compensation.

## 5. Visual originality boundary

### Required visual language

The target is a **paper-cut + woodcut + screen-print / ink-and-parchment hybrid**:

- warm fibrous substrate;
- chunky layered paper reliefs;
- ink-like contour edges;
- selective woodcut-style hatching;
- restrained print misregistration;
- thread/signal line motifs;
- wax, card, worn paper and tarnished fastener materials;
- fixed orthographic gameplay presentation;
- color used functionally, with non-color cues preserved.

### Sources permitted for inspiration

Use broad historical/material categories rather than one contemporary artist or one commercial game:

- early printed woodcuts and relief-print mark making;
- historical maps, cadastral/fortification diagrams and manuscript marginal systems;
- bookbinding, laid paper, rag paper and deckled-edge material;
- sealing wax, twine, brass/tarnished metal fasteners and map pins;
- screen-print registration artifacts and limited-ink workflows;
- paper theatre / layered relief construction;
- historical heraldic geometry only at the level of general shape language, never copied coats of arms.

### Sources prohibited as style targets

- "make it look exactly like [living artist]";
- direct tracing or paint-over of game screenshots;
- copying a contemporary game's palette, building silhouettes or UI skin as a set;
- prompt-based generation naming a living artist for production assets;
- competitor screenshots in final asset-source folders.

The committed visual board in this phase is an **original abstract grammar board**, not a collage of copyrighted game art.

## 6. Public-marketing originality rules

### Prohibited claims

Do not market the game as:

- "9 Kings but better";
- "The King is Watching without the bad RNG";
- "Thronefall meets X" as a primary store identity;
- "the spiritual successor to" any game without rights/authorization;
- "a clone of" or "our version of" a competitor;
- "exactly like [competitor] but...";
- "from the makers of" any unrelated property;
- compatible/officially associated with a competitor unless actually authorized.

Do not use competitor logos, store capsules, characters, screenshots, proprietary fonts, or recognizable iconography in comparison ads.

### Allowed descriptive language

Use product-truth statements:

- compact one-board strategy roguelite;
- physical command-network strategy;
- telegraphed threats;
- low-micro planning;
- short complete runs;
- paper-cut / woodcut strategy-map presentation;
- build-defining topology and priorities.

Comparables may appear in private research and clearly factual press conversations, but the product must stand on its own hook.

## 8. Mandatory originality rule

At every milestone, reviewers must be able to answer:

1. What player problem is this feature solving?
2. Why does Charterwake need it?
3. What is structurally different from the closest reference?
4. Does any name, layout, icon, progression element or composition feel sourced from one identifiable game?
5. Can its source and license be proven?
6. Does it strengthen the command-network identity?

A "no" or "unclear" answer on items 2, 3, 5 or 6 blocks milestone closure until corrected.
