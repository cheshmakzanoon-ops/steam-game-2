# Phase 006 — Brand vocabulary guide

**Project:** Charterwake: The Last Relay  
**Status:** APPROVED PREPRODUCTION BRAND BASELINE  
**Date:** 2026-09-22  
**Public-name status:** PROVISIONAL / AMBER

The brand language should feel like a practical damaged manuscript being repaired under pressure: concrete, tactile, legible, restrained and specific. It must not imitate the marketing vocabulary of the project's reference games.

## 1. Voice

Use:
- short declarative rules;
- material language: ink, paper, thread, seal, charter, relay, line, ash, brass, fiber;
- civic/military language: Watch, Warden, Keep, priority, route, ledger, breach, repair;
- consequences stated before flourish;
- dry, restrained humor;
- words that help the player understand state.

Avoid:
- lore-first sentences when a rule is needed;
- faux-archaic grammar;
- excessive Latin;
- generic fantasy superlatives;
- modern meme language;
- copy that hides uncertainty;
- grand claims about destiny, prophecy or saving the universe.

## 2. Product naming hierarchy

### Full public working title

**Charterwake: The Last Relay**

Use the full form on:
- first reference in formal documents;
- store/capsule/key-art drafts;
- press-kit header drafts;
- legal/naming-review material.

### Short form

**Charterwake**

Use after the full title has been established, in:
- internal documentation;
- changelogs;
- ordinary UI/menus where the full subtitle would add clutter.

Never abbreviate the public title to initials in player-facing copy.

### Subtitle

**The Last Relay**

The subtitle explains the emotional/world hook; it is not a separate mode, campaign or franchise marker.

Rules:
- title case exactly as written;
- colon between primary title and subtitle in plain text;
- no dash/slash variants;
- the subtitle may appear on a second visual line in logo/key art;
- do not append extra taglines to the formal title.

## 3. Canonical run vocabulary

Use these exact phase names:

1. **Forecast**
2. **Council**
3. **Build**
4. **Route**
5. **Production**
6. **Siege**
7. **Aftermath**

The player completes **15 Watches** across **three Acts**.

Act display names:

- **Act I — First Lines**
- **Act II — Frayed Charter**
- **Act III — Last Relay**

The generic unit of progression is **Watch**, displayed as `Watch 01` through `Watch 15`. Do not invent fifteen ornamental Watch titles unless later narrative work has a concrete need; boss identity is already enough differentiation.

## 4. Difficulty vocabulary

The difficulty system uses **Oaths**.

Provisional display names reserved for the six launch Oath slots:

1. **Oath I — Thin Stores**
2. **Oath II — Open Edge**
3. **Oath III — Frayed Circuit**
4. **Oath IV — Hard Watch**
5. **Oath V — Broken Reserve**
6. **Oath VI — Hushed Crown**

Phase 062 owns the exact mechanical effects. These names do not authorize mechanics before that phase. If a later mechanic makes a name misleading, change the name through design change control rather than forcing mechanics to fit branding.

## 5. Command-network vocabulary

Keep the already locked priority names:

- **Crown** — highest operating priority;
- **Charter** — normal operating priority;
- **Dormant** — intentionally off while remaining connected.

Core terms:

- **Command** — non-stockpiled operational bandwidth;
- **Load** — amount of Command required by an operating structure;
- **Port** — cardinal connection point;
- **Link** — legal connection between compatible ports;
- **Circuit** — player-readable connected operational grouping;
- **Relay** — structure/rule that changes network reach/capacity;
- **Resonance** — redundant valid paths to the Keep;
- **Cut point** — vulnerable network location whose loss disconnects downstream state;
- **Severed** — physically broken link;
- **Isolated** — no valid path to the Keep;
- **Unpowered** — connected/eligible but not admitted under available Command;
- **Powered** — admitted to operate this Watch.

Do not use electricity words such as voltage, amperage, battery or grid load unless a tooltip is explicitly explaining that the system is *not* an electrical simulation.

## 6. Resource vocabulary

Canonical player-facing resources:

- **Supply**
- **Material**
- **Insight**
- **Command**

Never pluralize these as collectible item names in headings. Prefer “12 Supply,” not “12 Supplies.”

## 7. Doctrine names

Canonical launch doctrine names remain:

- **Iron Charter**
- **Verdant Compact**
- **Lantern Synod**
- **Free Marches**

A doctrine is a rules identity, not a faction with separate simulation. Use “doctrine” consistently; do not alternate with class, house, deck, civilization or hero.

## 8. Enemy-family names

Canonical family labels:

- **Raider**
- **Hush**
- **Siege**

Use family as a classification, e.g. “Raider enemy,” not as a replacement for the enemy's individual name. Do not rename Hush enemies as undead, demons or corruption unless a later approved content definition explicitly requires such language.

## 9. Capitalization and punctuation

Capitalize formal game terms when they refer to the mechanic:
- Command, Load, Watch, Act, Oath, Keep, Crown, Charter, Dormant, Forecast, Council, Build, Route, Production, Siege, Aftermath, Resonance.

Lowercase ordinary-English uses:
- “the building is dormant” is allowed only when not referring to the priority state; prefer “set to Dormant” when the mechanic is meant.

Use:
- en dash for title/subdivision labels: `Act II — Frayed Charter`;
- colon for formal title: `Charterwake: The Last Relay`;
- numerals for Watch numbers;
- sentence case for ordinary UI labels unless the term is a proper/canonical mechanic.

Stable IDs use lowercase snake_case and never contain the marketing title.

## 10. Forbidden cliché / imitation list

Do not use as default marketing/world copy:

- “epic”
- “ultimate”
- “legendary” as generic quality praise
- “ancient evil”
- “chosen one”
- “dark lord”
- “save the world”
- “destiny awaits”
- “build your empire”
- “command an army” when the player does not directly control one
- “break the game”
- “infinite combinations”
- “X meets Y”
- “X but better”
- “spiritual successor” without rights/authorization
- “deckbuilder” or “cards” for the core system
- “city builder” when describing the primary strategic object without qualification
- competitor-specific taglines, icons or activation metaphors.

## 11. Accessibility / controller language

Every player-facing term required to make a decision must be available through focus, not hover alone. Short state terms should survive UI scaling and controller glyph layouts. Do not encode state only through color or decorative iconography.

## 12. Change rule

New named systems require:
1. a distinct player-facing need;
2. a stable internal ID independent of display name;
3. originality review;
4. localization-safe spelling/punctuation;
5. update to the lexicon;
6. owner approval if the term changes a locked Phase 001–005 concept.
