## Normal-path fixtures required later

### N1 — First Watch comprehension

A new player:
- identifies Keep/network/scarcity/threat;
- finds a meaningful choice;
- previews and changes it;
- commits;
- sees the expected resolution.

### N2 — Mid-run mastery

An established build:
- has a readable synergy;
- has a readable vulnerability;
- player predicts both;
- resolution confirms the prediction.

### N3 — Final-run explanation

After victory or defeat:
- player can identify a pivotal Watch;
- recap identifies the same decisive chain;
- player names a different possible plan.

---

## Boundary fixtures required later

### B1 — Command exactly at capacity

UI and preview show no phantom overload. Increasing Load beyond capacity changes a deterministic known set of powered states according to priority.

### B2 — Vulnerable cut point

Preview, damage, graph recalculation and recap agree about downstream isolation.

### B3 — Maximum practical board complexity

Late-run state remains inspectable at target camera/UI scales.

### B4 — Controller + UI scale

Same representative planning choice is reachable and understandable without pointer hover.

### B5 — Known-resolution skip

1×, 2×, 4× and allowed skip produce identical authoritative outcome and preserve a usable summary.

---

## Failure/recovery fixtures required later

### F1 — Fair network-collapse loss

Loss scores at least 14/16 on FAIR_LOSS_RUBRIC.md and contains no category score of 0.

### F2 — Hidden-rule injection test

A deliberately hidden decisive rule must be rejected by the rubric/gate rather than rationalized as difficulty.

### F3 — Recovery without chores

A damaged surviving board offers a meaningful recovery tradeoff; the optimal sequence is not merely repetitive repair confirmation.

### F4 — Save/reload equivalence

Same saved planning state reconstructs the same authoritative board/network allocation before resolution.
